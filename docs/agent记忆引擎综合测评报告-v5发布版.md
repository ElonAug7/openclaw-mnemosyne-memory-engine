> **版本状态**：本文档为当前最新发布稿（v5），对应 **Mnemosyne v4.5-Pro（2026-08-09 构建）**。
> 历史版本：v1-v3 为内部迭代稿，v4 为初版最终稿；**v3 及更早版本已废弃，请勿对外发布**。

> 测试台：`~/mem-bench/harness/`（可复现，见 §3.4）｜ 阅读器/判分器：DeepSeek-chat（temperature=0，LLM-as-judge，人工抽查审计一致率 94%）

## 1. 执行摘要

1. **Mnemosyne v4.5-Pro 为参测记忆引擎中的最优**（T2 端到端 0.562；五种权重设置下排名稳定第一），相对 BM25 基线优势为 1 题（63 vs 62/112，统计上不显著，表述为"占优"）。
2. **强结论（可发布）**：记忆引擎显著优于无记忆基线（0.562 vs 0.161，**+0.40**）；全上下文上界 0.830，仍有 0.27 提升空间。
3. **v4.5-Pro 相对 v4.5 的真实增量**：①`qa` 管线从 0.393 提升到 **0.554**（上一构建 → 本构建，+0.161，hybrid 双路召回集成生效）；②`search` 入口与 v4.5 行为一致（0.562）；③修复高亮标记泄漏；④refusal/time 模块已挂入 search 钩子（refusal 待校准）。
4. **所有引擎共同短板**：时序推理（≤4/10）、跨语言（≤2/6）、语义改写（≤7/10）、"旧信息压过新信息"导致的跨会话一致性下降。
5. **v4-Pro keyword 层 0.000 为整句子串匹配设计缺陷**（证据链完整，v4.5 双关键词组合检测已修复）。

## 3. 测评方法

### 3.1 档位与公式（统一文档化）

| 档位 | 配置 | 公式 |
|---|---|---|
| T0 极简 | 无 LLM/embedding，纯本地检索 | 检索综合 = 0.5×Recall@5 + 0.3×MRR + 0.2×Acc@1；拒答另列（分离阈值法） |
| T1 轻量 | 语义融合检索，无 LLM 阅读器 | 同上 |
| T2 主流 | 检索注入 + DeepSeek 阅读器 + 严格 judge | 端到端综合 = 判分正确率 |
| T3a/T3b | 对照组：全上下文 / 无记忆 | 同上 |

加权总分 = 0.3×T0 + 0.3×T1 + 0.4×T2；缺档引擎按剩余档位归一化。

### 3.2 判分协议
阅读器允许合理推断、无信息必须拒答；判分器规则：事实类"未提及"判错、弃权类编造判错、中英等价表述判对。**人工抽查 88 条，与 LLM judge 一致率 94%**（分歧全为 judge 假阴性，方向为低估，不改变排名）。

### 3.3 参测对象
Mnemosyne v4.5 / v4.5-Pro（search+qa 双入口）/ v4-Pro、TencentDB Agent Memory 0.3.6、BM25、BM25+本地嵌入混合、精确匹配基线、T3a/T3b 对照。
**agentmemory（rohitg00）**：无宿主观察管线，仅精确词召回可用，无法公平评测（已排除并记录）。

### 3.4 可复现指引
```bash
# 仓库（GitHub，被墙环境用 ghfast.top 镜像或 codeload tarball）
# https://github.com/ElonAug7/openclaw-mnemosyne-memory-engine
cd ~/mem-bench/harness
python3 dataset/build_dataset_v2.py       # 数据集（85 消息/112 查询，LoCoMo 式中文子集）
python3 run_bench_v2.py                   # v4.5/v4-Pro/BM25/Tencent/对照 全量（约 30 分钟）
python3 run_bench_v45pro.py               # v4.5-Pro search 入口（约 10 分钟）
python3 run_qa_v45pro.py                  # v4.5-Pro qa 入口（约 10 分钟）
python3 gen_scorecard.py                  # 评分卡 + 权重敏感性
python3 gen_chart.py                      # 可视化 SVG
# 结果: results/*.json + bench_chart.svg
```
环境：Node v22.23.2；DeepSeek API 仅用于 T2 阅读器/判分（temperature=0）；无其他外部依赖。

## 5. v4.5-Pro 双入口专项（本构建 vs 上一构建）

| 检查点 | 上一构建 | 本构建（2026-08-09） | 结论 |
|---|---|---|---|
| `qa` 检索基底 | keyword-only | **hybrid 双路召回** | 0.393 → **0.554**（+0.161）✅ |
| search 模块钩子 | 无 | refusal + time 已挂入 | search 行为与 v4.5 一致（refusal 未校准不触发） |
| 高亮标记 | `⟪$1⟫` 泄漏进 sources | `**$1**` 纯展示标记 | 修复 ✅ |
| refusal 拒答 | 未校准 | 未校准（0/112 触发） | 待校准（见 §7） |
| rewrite/multihop/crosslang | 扩展率 ~10% | queryVariants 平均 1.1（~10%） | 待放宽触发条件 |
| time 时效 | 全 False | 部分生效（qa 胜例：时序 3/10、冲突处理 3/4） | 初见成效 ✅ |

**qa 相对 search 的差异（7 题：胜 3 负 4）**：qa 胜在时序类（"第一次去成都"→去年、"健身以前频率"→每周三次晚上）——time 模块的时效/冲突信号开始起作用；负在部分召回（"喝什么茶""下一个旅行目的地"漏检）。

## 6. 各引擎诊断

1. **TencentDB AM 画像误导**：persona 注入使语义改写 7/10 最佳，但知识更新 2/8、个性化 2/10、多跳 2/12 全场最差——静态画像（Employer: ByteDance / 住上海）系统性误导阅读器。**任何画像注入必须带时效标记与冲突消解**（v4.5-Pro time 模块的设计正是对此的回应）。
2. **BM25 意外强项**：时序 4/10、跨会话一致 4/6（实体精确匹配）；跨语言 0/6 拖死总分。
3. **v4-Pro keyword 缺陷**：整句子串匹配（短词命中/长问句全灭），已在 v4.5 双关键词组合检测修复。
4. **T3a 上界非 1.0**：全量上下文下阅读器仍受旧信息干扰（"Which company"答字节跳动）、跨语言 5 错、弃权 3 错——验证 LongMemEval 论文"持续交互中准确率下降"机制。

## 8. 局限性与适用边界（场景化）

### 8.1 适用场景
- 隐私敏感 / 完全离线（无 LLM 依赖，T0/T1 全离线可跑）
- 轻量部署（448KB vs Tencent 452MB）
- 高频实时记忆（即录即搜，秒级）
- 中文为主的对话记忆（双关键词组合 + 中文分词）

### 8.2 失效边界（具体案例，LoCoMo-CN 实测）
- **语义改写**：改写问法后召回下降（"用户的居住地是哪个城市"命中、"家在哪个城市"漏检——两版均如此，3/10 与 2/10）
- **跨语言**：中文存、英文问——即使全上下文上界也只有 1/6；crosslang 模块目前扩展率不足（queryVariants 1.1）
- **时序/旧信息**：全部引擎"健身时间"类更新题会被旧值误导（v4.5-Pro qa 3/10 已是最好之一）；"用户在哪里工作"两版均答旧公司"字节跳动"
- **多跳**：需要拼接 2+ 条记忆的推理题 5-7/12——检索能召回证据，但阅读器/证据链组织不稳定

### 8.3 局限声明
- 112 查询为子集规模，引擎间 1-3 题差异需 McNemar 检验（当前不显著）
- 判分器存在假阴性（人工审计 94% 一致，方向低估）
- 单阅读器（DeepSeek-chat），建议双模型交叉判分
- Tencent 未启用向量嵌入（无 key），启用后需复测
- 中文子集为自建（公开基准以英文为主），跨语言维度解读需谨慎

## 9. 结论与改进路线图

**结论**：v4.5-Pro 是当前参测引擎中综合最优（T2 0.562/qa 0.554，弃权 18/18、冲突处理 3/4、时序 3/10 领先）；记忆引擎相对无记忆基线 +0.40 是稳健可发布的强结论。

**v4.5-Pro 下一步（按 ROI）**：
1. **refusal 校准**：用本测试 19 弃权 + 93 事实做分数分布标定，落地三档置信拒答（校准后 T1 档弃权从 0 → 预计 15+/18）
2. **放宽 rewrite/multihop/crosslang 触发**：对"为什么/如何/先…还是"类查询强制分解，英文查询强制双语扩展（当前扩展率仅 10%）
3. **time 模块全面生效**：半衰期衰减接入排序阶段（当前仅 qa 部分场景）
4. **跨语言**：crosslang 实体映射扩展到测试集实体（Shenzhen/Tencent/团子→Tuanzi 等），目标 ≥4/6
5. **扩样本**：≥300 查询（弃权 ≥30）后重跑显著性检验，冲刺可对外发布的 Benchmark 榜单
